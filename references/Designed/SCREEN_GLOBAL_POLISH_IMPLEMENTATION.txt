# 2. RESPONSIVE VIEWPORT FIT — HIGHEST PRIORITY

The Games portfolio is a composed interface, not a normal vertically scrolling website.

The site currently behaves inconsistently across desktop/laptop resolutions: some routes fit the viewport while others create vertical scrolling.

Fix this globally.

## Core rule

Supported screen layouts must adapt their:

- spacing;
- panel padding;
- typography;
- media dimensions;
- grid proportions;
- gaps;
- rails;
- header sizes;

so the composition stays inside the available viewport.

Do NOT solve responsive problems by introducing page-level scrollbars.

Do NOT create internal scrolling panels as a workaround.

Do NOT arbitrarily hide content.

Do NOT allow a page to overflow just because a lower-resolution laptop is being used.

The interface should behave like a composed game/menu UI.

## Target desktop/laptop checks

At minimum test:

- 1280 × 720
- 1366 × 768
- 1440 × 900
- 1600 × 900
- 1920 × 1080
- 2560 × 1440

The screen should preserve the same overall composition at all these sizes.

Use responsive CSS rather than hardcoding one resolution.

Potential tools include:

- `clamp()`
- viewport-aware sizing
- responsive spacing tokens
- responsive typography
- `minmax()`
- aspect-ratio constraints
- dynamic grid fractions
- max-height/media constraints
- breakpoint-specific density adjustments

Avoid scaling the entire page through one giant `transform: scale(...)` unless there is an exceptionally strong technical reason.

Prefer responsive component geometry.

## Important

A lower-resolution screen should feel like the same interface seen through a smaller viewport — not a different document.

# 3. MEDIA CORNER TREATMENT

Media currently risks visually colliding with the angular geometry of its tactile container.

Introduce subtle rounding ONLY to the actual media viewport.

## Principle

STRUCTURE = SHARP

CONTENT = SLIGHTLY SOFTENED

The outer tactile frame remains angular.

The inner:

- image;
- video;
- gameplay capture;
- screenshot;
- gallery viewport;

receives subtle rounded corners.

Recommended radius:

    10–12px

Smaller thumbnails may use approximately:

    8px

Do NOT round:

- outer tactile panels;
- title plates;
- buttons;
- navigation rails;
- section plates;
- contextual rails;
- major content containers.

The media viewport must use clipping/overflow so images and video respect the same radius.

Maintain enough internal frame padding that the rounded media does not touch or collide with the outer clipped corners.

Apply consistently across:

- Overview project showcase;
- Projects Overview cards;
- Project Detail video;
- Project Detail gallery;
- Role Detail practice media;
- Case Study evidence media;
- other shared media frames.

Preserve all correct source aspect ratios.

Never stretch media.

# 4. CONTAINER / BACKGROUND SEPARATION

The current background direction is NOT finalized.

Do NOT change the global page background during this task.

Do NOT activate `dark-background.css`.

Do NOT decide between cream, grey or black.

Instead, improve the distinction between the existing background plane and tactile cream surfaces using depth.

## Goal

Cream containers should clearly read as physical UI objects sitting above the page background.

Explore subtle shadow treatment around major cream surfaces.

This should work with the site's existing:

- black outline;
- red underslab;
- offset hard shadow;
- cut-corner geometry.

We do NOT want generic modern web-card shadows.

Preferred feeling:

    printed / layered physical interface
    +
    small amount of ambient separation

Possible approach:

- retain existing compact hard offset shadow;
- add a very restrained soft/ambient shadow around the outer surface;
- keep opacity low;
- avoid enormous blur radii.

If useful, introduce one shared token such as:

    --ui-shadow-ambient

Do not independently invent different shadows per screen.

Apply selectively to major physical surfaces, not every tiny control.

Likely candidates:

- `ui-surface`
- print/content panels
- major media containers
- role cards
- project cards
- case-study shells

Do not muddy text or create obvious glowing halos.

The result should primarily improve separation from the background.

# 5. BUTTON INTERACTION LANGUAGE

The existing button lift is good but insufficient by itself.

Create a consistent site-wide color interaction language.

## Neutral button

REST:

    cream background
    black text/icon
    black outline

HOVER:

    red background
    cream text/icon
    retained black outline
    small upward physical response

PRESSED:

    black background
    cream text/icon
    reduced/collapsed shadow
    slight downward movement

## Primary red button

REST:

    red
    cream content

HOVER:

    darker red
    cream content

PRESSED:

    black
    cream content

## Motion

Keep the existing tactile lift.

Target:

    approximately 1–3px

The button may receive a tiny one-time "kick" / wiggle feeling when entering hover, but:

- do not loop;
- do not shake continuously;
- do not make text difficult to read.

The interaction should feel like selecting an item in a game menu.

---

# 6. ARROW MICROINTERACTION

Directional arrows inside CTAs should respond to hover.

On parent button hover:

RIGHT arrow:

    translateX(+2px to +3px)

LEFT arrow:

    translateX(-2px to -3px)

Vertical arrows should follow their respective direction if they exist.

Keep it fast and restrained.

The arrow must return immediately when hover leaves.

Do not animate continuously.

# 12. VERTICAL RAIL DEPTH

The large left and right vertical rails currently sit beside the center page but could integrate more convincingly as part of one physical interface.

Add restrained depth where the rails meet the central content area.

## Desired result

The visual hierarchy should become:

    left rail
        ↓
    central content plane
        ↑
    right rail

while all three still feel connected.

Explore an inward-facing shadow along:

- right edge of left rail;
- left edge of right rail.

Possibly combine:

- small hard edge shadow;
- subtle ambient shadow.

Do NOT add giant shadows around the outer viewport.

Do NOT make rails appear detached or floating far above the page.

This should simply clarify the layering.
