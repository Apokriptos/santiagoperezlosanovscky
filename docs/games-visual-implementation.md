## Architecture and locked geometry

`styles/shell.css`, `src/shell.js`, and `src/router.js` are unchanged. The approved global variables remain centralized there: 251px left and 134px contextual rail. Actual browser viewports at **1434 × 913** resolve to **251 / 1183** without a contextual rail and **251 / 1049 / 134** with it. Pages only compose their internal rectangles. No page-level rail-width definitions or outer-shell grids were introduced.

The right contextual index remains generated by `src/app.js` from Projects, Roles, or CaseStudies. It now has small sequential markers, compact wrapping labels, restrained dividers, and one clear active entry, over the existing production artwork. It remains quieter than the primary rail.

`config`, `navigation`, `Projects`, `Roles`, and `CaseStudies` remain the same centralized architecture. `config.copy` collects section-introduction placeholders. Projects gain optional `buildProvider` and `buildNote` fields; no build provider, permissions, or distribution terms are fabricated.

The only interaction correction is in `src/components.js`: after a case-step render, the local horizontal rail reveals the active step. Previously, a direct link to a late step could leave its selected item outside the horizontal viewport. This changes neither routing nor vertical page scroll.

## Deliberate deviations and remaining issues

- Current shell widths take precedence over older mockup rail proportions.
- Every screen uses the approved cream/black/red identity rather than reproducing grayscale mockup styling.
- Portraits, project imagery, footage, final copy, real experience entries, case conclusions, build links/terms, CV, email/LinkedIn, and personal biography/timeline details remain explicit placeholders. Sample names and claims inside mockups were not imported.
- Empty tags/experience arrays do not produce invented content. Missing actions remain disabled or labeled forthcoming. Contact's configured GitHub link remains a real external link.
- Long pages scroll within the approved desktop content rectangle. They are not squeezed into a single fixed-height poster. On mobile, the document scrolls normally and only step navigation scrolls horizontally.
- Native PDF embedding is retained rather than adding a new PDF runtime. Actual PDF rendering/downloads, real video playback, external-provider download behavior, and production hosting still require real files/URLs and cannot be fully verified with the current missing media.
- No known routing, shell geometry, or horizontal-overflow defects remain in the tested viewports. Aobscura was not modified. No backend or Books branch implementation was added.
